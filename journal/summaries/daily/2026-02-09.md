## Key Decisions

- **Add Research Spike on Weaver Integration Approach** — Evaluate CLI, MCP server, and hybrid approaches to determine the best method for interacting with the Weaver registry before committing to implementation. This became a prerequisite for subsequent design work.

- **Renumber Research Spikes** — Moved the fix loop design research from RS2 to RS3 to make Weaver integration the first research spike.

- **Schema Checkpoint Recovery** — Default to aborting on checkpoint failure in the non-interactive Coordinator, but allow interface layers to override this behavior via a boolean return option on the callback. This avoids the impossible problem of asking for user input in a script.

- **SDK Init File Parsing Scope** — Support the clean NodeSDK constructor pattern from the spec's example, with a fallback mechanism for unrecognized patterns. For complex cases, write a separate instrumentation export file and provide manual integration instructions rather than trying to handle every edge case.

- **Coordinator Error Classification** — Create a three-tier error handling system: "abort immediately" for unrecoverable issues, "degrade and continue" for isolated failures, and "degrade and warn" for non-blocking problems. Use the PR summary as the single reporting mechanism.

- **Semantic Deduplication for Journal Entries** — Check for duplicates using both commit timestamp and message to catch cherry-picked and rebased commits, not just exact hash matches. Split entries into blocks before comparing to avoid false positives across different entries.

- **Track Test Failures and Exit Non-Zero** — Make the test script track failures and exit with a non-zero status code when tests fail, rather than unconditionally printing success.
