# Daily Summary — 2026-07-11

## Narrative

The developer spent the day debugging a telemetry export issue and then documenting the fix. They'd been puzzled about why telemetry data stopped flowing around July 6th, and after working through it with the Spinybacked Orbweaver team, realized the culprit wasn't code—it was that the local OpenTelemetry Collector had stopped running. The developer had likely restarted their machine that day and never brought the collector back up, so OTLP exports were silently failing in the background.

With that mystery solved, the developer tackled the underlying instrumentation problem. The agent had no real guarantee that three critical attributes—`gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, and `commit_story.ai.section_type`—would be included in spans. Since the Spinybacked Orbweaver dashboard queries depend on them (per PRD #980), the developer promoted these attributes from recommended to required in the telemetry schema. This establishes a durable contract ensuring future instrumentation runs will actually include them rather than treating them as optional.

While investigating, the developer also found and fixed a broken symlink in `node_modules` that was pointing to local commit-story source code, restoring it so future commits would use the real local version instead of falling back to the published one.

The developer then updated PROGRESS.md to document the attribute promotion work.

## Key Decisions

- **Promote token usage and section type attributes to required in telemetry schema** — Recommended status isn't a forcing function for instrumentation agents to actually include attributes. Promoting these three attributes to required documents the durable contract that downstream dashboard reliability depends on.
