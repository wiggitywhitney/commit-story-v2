## Key Decisions

- **Preserve existing error handling**: When instrumenting functions with try-catch blocks, wrap the entire function with a span rather than restructuring the error handling. This keeps the span clean and respects the original code logic.

- **Reuse attributes across contexts**: When the same semantic concept appears in multiple places (like entry counts across daily, weekly, and monthly summaries), use a single attribute key rather than creating duplicates. This was applied to `commit_story.summary.entry_count`.

- **Skip instrumentation for pure synchronous utilities**: Functions containing only synchronous logic and no I/O operations don't warrant spans. Document these decisions in instrumentation reports rather than adding unnecessary tracing.

- **Defer path normalization fixes**: Raw filesystem paths in span attributes trigger data quality advisories, but don't add new imports solely to normalize paths. Flag these as lower-priority findings for future work when code context allows.

- **Graceful error handling stays untracked**: When inner catch blocks handle expected failures gracefully (like missing directories or per-item failures), don't record those as errors in the span. Only record unexpected exceptions at the outer span level.
