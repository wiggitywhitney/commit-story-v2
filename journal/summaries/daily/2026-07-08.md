# Daily Summary — 2026-07-08

## Narrative

The developer spent the day fixing several interconnected issues in the commit-story journaling system that had been causing silent failures and data loss.

The first major problem was environment variable leakage. When commits were made from inside Claude Code, the Datadog gateway environment variables (`ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS`) were being inherited by the post-commit hook's child process. This caused the hook's own LLM calls to fail silently with 400 errors, leaving behind placeholder text instead of real journal summaries. The developer fixed this by updating the hook installation script to strip both variables using `env -u` before invoking node across all three invocation paths (vals exec, plain node, and npx fallback). They discovered the initial fix had missed one path, caught it through inspection, and then carefully reinstalled the corrected hook in all nine affected repositories across the codebase.

Next, the developer tackled a dedup logic bug where stale failure-placeholder files were being treated as valid content, preventing regeneration on retry. They created a shared helper function to detect failure placeholders and wired it into eight different dedup-check call sites across journal and summary managers. This meant that when a generation failed and left behind a placeholder file, the next run would regenerate it instead of skipping it as a duplicate. The fix preserved all existing behavior for real content while opening up the regeneration path for stale placeholders.

While working on placeholder detection, the developer discovered an overly aggressive dialogue-extraction filter. Journal entries weren't capturing conversations even though substantial back-and-forth had occurred. The root cause was in the dialogue prompt—it was treating quotes that overlapped with the summary's content as redundant and discarding them, when they should've been kept as supporting evidence. The developer clarified the prompt to distinguish between "supports the summary" and "is redundant with the summary." They also tightened the placeholder detection logic to match only the bracketed format (like `[Daily summary generation failed]`) instead of bare substrings, since real narrative content could casually mention "generation failed" in prose and get misclassified. Additionally, they fixed a data-loss window in the journal-manager code by combining the stale-placeholder removal and entry append into a single write operation instead of two separate writes.

Finally, the developer added token usage metadata capture to LLM invoke spans. The metrics downstream had no groupable dimensions because the spans weren't actually recording the usage metadata that the models were providing. They added the same pattern at all six LLM invoke call sites to capture both input and output token counts on OpenTelemetry spans, making the token usage data observable in monitoring systems.

## Key Decisions

- **Strip ANTHROPIC_BASE_URL and ANTHROPIC_CUSTOM_HEADERS from all three post-commit hook invocation paths** — Claude Code sets these vars to route API calls through the Datadog AI Gateway; when inherited by the hook's child process, they cause silent failures. Stripping unconditionally (rather than conditionally based on DD_API_KEY) was chosen after empirical testing confirmed the gateway header validation doesn't depend on DD_API_KEY.

- **Create shared failure-placeholder detection helper** — Avoid duplicating placeholder-detection logic across multiple call sites by checking for the bracketed format pattern.

- **Treat failure-placeholder journal entries and summaries as regenerable rather than duplicate** — Stale placeholder blocks are removed and regenerated, while real-content duplicates continue to be correctly skipped.

- **Clarify dialogue prompt to distinguish between "supports the summary" and "is redundant with the summary"** — The model was conflating these concepts; the prompt now explicitly states that overlap with summary content is acceptable and quotes supporting key moments should be kept.

- **Tighten failure-placeholder detection to match only bracketed format** — Prevents real narrative content casually mentioning "generation failed" or "extraction failed" in prose from being misclassified as stale placeholders.

- **Combine stale-placeholder removal and entry append into single write operation** — Eliminates a data-loss window where a crash between two separate writes could drop an entry entirely.

- **Capture gen_ai.usage token counts on OpenTelemetry spans** — Makes token usage data observable and groupable in monitoring/tracing systems.
