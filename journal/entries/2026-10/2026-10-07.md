## 12:43:25 PM CDT - Commit: 38d2d66

### Summary
The Traceloop auto-instrumentation initialization was fixed to actually work when `COMMIT_STORY_TRACELOOP=true` is set. The LangChain instrumentation call in `traceloop-init.js` was passing no argument to `manuallyInstrument()`, which caused it to crash trying to destructure a `callbackManagerModule` property that didn't exist. The developer updated it to import and pass `@langchain/core/callbacks/manager` as an argument, so LangChain spans now get produced correctly.

The MCP instrumentation call was removed entirely. The reasoning is straightforward: this file only loads in the CLI, which never imports the MCP SDK. The MCP server runs as a separate process and never loads this initialization file, so the call couldn't do anything useful. The MCP instrumentation also only traces requests the server sends, not the tool calls it receives, so it wouldn't have captured incoming spans anyway.

The test file was rewritten to use spies on the real instrumentation classes instead of mocking them, which is what originally hid the crash. The tests now verify that LangChain instrumentation activates with the correct callback manager module when the flag is set, that MCP instrumentation doesn't activate (since it's not called), and that nothing activates when the flag is unset or false.

A new test was added to the hook tests to verify that `COMMIT_STORY_TRACELOOP` set by the caller actually reaches the commit-story process, catching the case where the environment variable gets lost in transit. The hook test output was also updated to include the traceloop flag in its assertions.
